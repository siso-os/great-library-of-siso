# Existing-owner adapter contracts

These are integration requirements, not claims that endpoints have been built.
Use current source instructions and the owner's actual tool contract. Do not guess
an MCP function, filesystem path, credential, schema alias or runtime identity.

| Owner | Send | Receive | Boundary |
|---|---|---|---|
| Existing task system | Original task reference, packet and final receipt hashes | Current owner/status and accepted or rejected work | The task remains canonical there; the attempt does not become a second task |
| Foundry | Question pin, decision, permitted source scopes, exclusions and acquisition limit | Source-native references, observation dates, query lineage, coverage and rights limits | Discovery is not source permission, identity truth or adoption approval |
| SISO Knowledge | Owner-resolvable source/span requests with current access and rights | Versioned source access and provenance receipts | Raw corpora and private payloads remain with Knowledge or the source owner |
| Evidence Engines | Candidate claims, source spans, support/challenge edges and declared dependence | Evidence review/adjudication references with limitations | A local research receipt stages candidates; it does not replace canonical claims |
| Existing execution owner | Original authorization, pinned packet, finite limits and allowed tools/effects | Actual run/actor identity, artifacts, usage, cancellation and recovery receipts | The runner must enforce permissions and budgets; the offline checker cannot |
| Great Library | Reviewed public-safe identity/evidence/learning references | Normal schema-validated Work/Event or immutable Release/Snapshot lineage | No direct promotion from a worker, no private packet or raw journal in public Git |

## Ordinary Chat without a runtime

An agent may read the current question through GitHub, perform authorized source
research, and return the same fields in prose or an owner-approved artifact. It
must not claim `prepare`, `record`, tests, a live collector or a saved canonical
handoff ran if no callable runner/save endpoint was used. The short prompt is
usable without pretending the full execution stack is present.

## Local or hosted coding agents

Use Node.js 20+ and a pinned Library checkout. Read `FRONTIER.md`, recover the
existing task owner, and verify the packet's source/kit pins before each new phase.
Keep the worker's allowed tools narrower than its general account permissions.
Source acquisition happens through existing connections, outside the compiler.
The compiler never executes a shell string or follows a source URL.

For another model/context, give the agent the generated `prompt` and access to the
same owner-held packet and cited artifacts. Author and session identifiers must
come from actual runtime observations when available; arbitrary labels are only
self-reported metadata. No installation into a global skill store is required.

## Explicitly authorized parallel research

Use a single packet/journal writer and disjoint worker artifacts. Assign each worker
one uncertainty, permitted source scope, expected return and remaining budget.
Independent collection can run concurrently only under the runtime owner's real
limits. The coordinator records one research receipt containing the reconciled
findings and aggregate child/setup/verification/retry costs. Do not count a shared
source or benefit twice. The critic must not silently inherit an author's conclusion
as its instructions.

There is no automatic spawn function here. Library implementation lanes still need
the canonical non-overlapping reservation Event before parallel work. This kit does
not override existing source-owner instructions or runtime placement constraints.

## A sustained adapter must prove all of these

Before activation, the execution owner must demonstrate a current compatible
runner, original authority and expiry, finite quota/account caps, non-overlapping
write scope, cancellation before the next external effect, durable outputs,
restart recovery, idempotent external requests, independent review routing, and a
verified destination for the learning return. Use idempotency keys for any future
external writes. A local journal lock is not a distributed lease or exactly-once
delivery system. Do not mount one journal over multiple hosts and assume it is.

No scheduler, daemon, API provider, model default, host, paid account or publication
policy is configured by this contribution. Account unknowns stay unknown.
